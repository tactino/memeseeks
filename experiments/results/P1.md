# P1 verification (2026-09-25)

`memeseeks` v0.1.0 CLI, run on the maintainer's private
collection (109 text-heavy memes, 25 labeled queries — only aggregate numbers here).

## Retrieval (`memeseeks eval queries.csv`)

| Machine | Routes | R@1 | R@5 | MRR |
|---|---|---|---|---|
| Windows laptop, CPU only (i7-1360P, torch 2.11.0+cpu) | OCR + CLIP (default) | 0.96 | 1.00 | 0.97 |
| GPU box (RTX 5090, torch 2.11.0+cu128) | OCR + CLIP (default) | 0.96 | 1.00 | 0.97 |
| GPU box | OCR + CLIP + VLM (`add --vlm`) | 0.96 | 1.00 | 0.98 |

Per route on both machines: OCR 1.00 / 1.00 / 1.00, CLIP 0.88 / 0.92 / 0.91, VLM 1.00 / 1.00 / 1.00.
These equal P0's `hybrid_no_vlm` and `hybrid` exactly, so the library code path reproduces the experiment code path.

## Open issues for P2

- CPU indexing at ≈ 5.6 s / image is too slow for libraries of thousands; profile OCR vs CLIP and consider a
  smaller CLIP model for the CPU tier.
- Each CLI call reloads the models; the P2 server should keep them loaded.
- Re-`add` loads OCR and CLIP even when there is nothing new to index.

## Environment finding

On Windows, a venv built from Anaconda's Python cannot load torch ≥ 2.9 (`WinError 1114`, `c10.dll`): Anaconda
ships MSVC runtime 14.29 next to `python.exe`, which shadows the system's newer runtime. Bisected: 2.8 loads,
2.9.1 / 2.10 / 2.11 / 2.14 fail; 2.11 loads on a uv-managed CPython. Documented in the README.
